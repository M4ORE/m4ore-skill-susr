# 場景：接到新客戶的第一週

## 30 秒先看這段

你剛簽下一家新客戶，預計三個月內交付永續報告書。過去第一週你要：跟客戶要資料、整理 20 個 Excel、看上年報告書找參考、決定議題池、寫 scoping 文件——平均吃掉 12 到 18 小時。

用 susr，第一週你只需要做兩件事：(1) 建 client workspace（一句話），(2) 把上年資料 fork 進來作 baseline。剩下的時間留給跟客戶開 kickoff 會議、確認重大議題範圍變化。

---

## 痛點

新客戶第一週的時間黑洞集中在「啟動成本」：

- **每個客戶要重新建檔**：資料夾結構、模板、引用慣例、命名規則
- **上年報告書（如果有）不是結構化資料**：你要從 PDF 翻出 KPI / 議題 / 行動，貼到新的工作檔
- **客戶交來的初步資料散在 5 種格式**：Excel、PDF、word、email 附件、共享資料夾連結
- **找不到「我去年怎麼處理類似客戶」的快速 reference**

這段時間沒有附加價值，但又繞不過。

---

## 過去怎麼做

典型 workflow（大概 12-18 小時）：

1. 開新資料夾 `/clients/<新客戶>/`，複製上次案子的模板（30 分鐘）
2. 把客戶寄來的初步資料分類整理進子資料夾（1.5 小時）
3. 翻上年報告書 PDF，把議題清單、KPI 清單、行動清單抄到 Excel（4-6 小時）
4. 寫 scoping 文件，跟客戶來回確認邊界與報告期間（3 小時）
5. 整理利害關係人聯絡名單（1 小時）
6. 開 kickoff 會前準備（2 小時）
7. 開 kickoff 會（1.5 小時）

第一週結束你大概還在第 3 步打轉。

---

## 用 susr 怎麼做

### Day 1：建 workspace（5 分鐘）

在 Claude Desktop 聊天視窗：

```
顧問：幫我建一個叫 acme-textile 的 client，紡織業，台灣上市櫃，
      合併報表邊界，報告期間 2025 年度，applicable standards 是 GRI 2021 + ISSB S1 + TW_FSC，
      embedding policy 用 twostage。

Claude：[呼叫 create_client_workspace]
       已建立 workspace：~/work/acme-textile
       - git initialized
       - SQLite brain: .susr/db.sqlite (schema v1)
       - shared/ snapshot copied (5 industry packs，含 textile.md)
       - _client.md 已寫入 frontmatter
       - entities/{topics,stakeholders,governance,kpis,targets}/ 已建空殼
       - projects/ 已建空殼
       下一步建議：上傳 Phase 1 scoping 決策 或 fork 上年資料。
```

完成，你的客戶 repo 就位。git history 從 0 開始，所有資料夾結構符合 susr 慣例。

### Day 1-2：fork 上年資料（如果有）（30-60 分鐘）

如果客戶過去找過你（或前手顧問），把上年 client repo 的 `entities/` 拷貝過來：

```bash
cp -r ~/work/acme-textile-2024/entities ~/work/acme-textile/entities
```

然後在 Claude Desktop：

```
顧問：把 entities/ 重新 ingest 進 brain，標記為「2024 baseline，待 2025 重評」。

Claude：[呼叫 brain ingest + timeline]
       已 ingest 28 個 topic / 7 個 stakeholder / 12 個 KPI / 8 個 target。
       每個都加了 timeline 一筆 action_type='ingest'，payload={baseline_year: 2024, status: 'pending_review'}。
       下一步建議：跑 health_check 確認 I1/I3 invariant 狀態。
```

接著建新年度 project：

```bash
cp -r ~/work/acme-textile-2024/projects/2024-sustainability-report \
      ~/work/acme-textile/projects/2025-sustainability-report
```

改 `_project.md` 的 framework_version（例如 ISSB 升級）+ reporting_period。

### Day 3：跑 health_check 看 baseline 狀態（10 分鐘）

```
顧問：跑 health_check on acme-textile。

Claude：[呼叫 health_check]
       ✓ schema v1
       ✓ sqlite-vec loaded
       ⚠ I1 violation: S6 (供應鏈管理) 為核心議題但 action chain 為空
          → 可能是 2024 行動已完結，2025 需要新行動
       ⚠ I3 violation: target/scope3-reduction 缺 verification_path
          → 2024 沒寫，2025 必補
       ✓ I4: 所有 datapoint 有 source_doc
       ⚠ I5: 2 個排放因子已 superseded (環境部 2024 v2 → 2025 v1)
          → 重算範疇 1 數值
```

短短 10 分鐘你就有了清晰的「第一週要先補哪幾件事」list。

### Day 4-5：scoping 對焦 + kickoff（4 小時）

scoping 文件可以用 `read_consultant_kb` 拉你過去的 scoping 模板，改幾欄就好。kickoff 會議 deck 直接從 entities + _client.md frontmatter 自動聚合。

## 省下的時間 / 提升的品質

| 項目 | 過去 | 用 susr |
|---|---|---|
| 建檔 / 模板 | 30 分鐘 | 5 分鐘 |
| 整理客戶資料 | 1.5 小時 | 30 分鐘 |
| 上年資料抽取 | 4-6 小時 | 30-60 分鐘 |
| scoping 文件 | 3 小時 | 1.5 小時 |
| 利害關係人名單 | 1 小時 | 從 entities/stakeholders/ fork |
| **第一週總時間** | **12-18 小時** | **3-5 小時** |

省下的不只是時間。品質提升在於：

- **上年資料 100% 帶 over**：不會漏抄某個 KPI
- **I1/I3/I4/I5 一上來就跑**：你知道哪些 baseline gap 要先處理
- **timeline 從 day 1 累積**：之後做確信時整年 audit trail 完整

---

## 進階提示

**如果是全新客戶（沒有上年資料）**：

跳過 fork 步驟，直接 `search_topics_universe(industry='textile', framework='GRI')` 拉產業議題池當起點。給客戶看 28 個候選議題比給空白 Excel 容易對焦多了。

**如果客戶過去由別家顧問做**：

把對方的報告 PDF 放進 `sourcedocs/2024/`，跑 ingest，brain 會抽出議題與 KPI 進 entities/。你會得到一份「上家顧問的成果結構化版」，作為今年的 baseline。

**如果你想累積「我服務過幾家紡織業」的方法論**：

完成這個案子後，用 `promote_to_consultant_kb` 把可重用的 insight（匿名化）提升到 consultant-kb。下次接紡織業客戶時 `read_consultant_kb` 就能拉出來。注意這條是**單向闘**——client 資料絕不自動流向 KB，必須你顯式 promote + confirm_token。

---

## 對應原則

- **Co-pilot**：susr 處理啟動成本，你的時間留給戰略對焦
- **Auditable Trust**：timeline 從 day 1 就在累積
- **顧問專屬功能**：consultant-kb 跨案子 reuse 你的方法論
