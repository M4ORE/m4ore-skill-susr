## Act

### Lessons Learned
- **Graceful Degradation 是 orchestrator skill 的關鍵設計原則**：susr 不是「全有或全無」— 沒有底層工具的 user 仍能拿到 80% 價值（SOP / 知識庫 / prompt 模板）。這比單純列依賴清單對 user 有用得多。
- **README 引用要用「公開可達」原則**：發現 README 引用 `plan.md` 但 `.gitignore` 排除它 — 任何 README 引用必須是 repo 內可達或外部公開連結，不能引用「私人草稿」。
- **user 中段提問會引出隱藏需求**：「他人需要裝嗎」這個問題促成 Graceful Degradation 段落，這原本不在 plan 內。把這種發現補回 README/Plan，避免後人重複問。
